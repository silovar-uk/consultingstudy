# Consulting Study｜次の一手を「実務判断の証拠」から再設計する（2026-10-20）

**対象**：https://silovar-uk.github.io/consultingstudy/#/cert-lab

**今回の判断**：「もう問題を増やす」ではなく、**一つの実務能力について何をもって習得の証拠とするか**を定義して、実際の判断メモの提出と独立した評価の準備を実装する。既存90問・A/B/Cの評価用9問は維持し、今回の2ケースは選択式の問題数に算入しない。

## 1. 初回リサーチ：コード・教材・既存の測定

最新のmainを確認。従来の90問は回答、採点、理由・自己点検を備える。A/B/Cパイロットは財務・統計・PMOそれぞれ3問の別状況を持つ。一方、これだけでは「実際の案件で根拠を整理して他人の判断を前進させられるか」の直接観測ができない。

- 元の63問は四択、他の27問は6形式。公式試験を網羅しているわけではない。
- A/B/Cでは問題間の難易度を等化しておらず、個別の正誤を実務能力の向上率には換算できない。
- 90問の問題ID・単元・出典・説明整備状況は `docs/question-audit-20261020.csv` にある。ただし**90問の各選択肢と解説の独立専門家査読は未了**。
- 学習ログはブラウザ内に保存され、クラウドの実学習ログを取得したわけではない。今回もユーザーデータの収集・送信は行わない。

### 一次資料

1. **ETS（2011）**：Hansen, *Evidence-Centered Design for Learning*。習得の主張と証拠と課題に加え、学習の成長、妥当性、アクセス可能性、学習効率などを考慮する。https://www.ets.org/research/policy_research_reports/publications/report/2011/imbu.html
2. **ETS（2003）**：Mislevyら、*A Brief Introduction to Evidence-Centered Design*。能力モデル・証拠モデル・課題モデルを対応させる。https://www.cn.ets.org/content/ets-org/research/policy_research_reports/publications/report/2003/hsgs.html
3. **PMI**：*Risks vs. issues*。未発生リスクと発生済み問題を区別し、問題ログには責任者・期限・影響などを記録する。https://www.pmi.org/learning/library/risks-vs-issues-project-failure-2328
4. **PMI**：2026年版PMPの出題範囲。価値、事業成果、関係者への働きかけを重視する。https://www.pmi.org/certifications/project-management-pmp/new-exam
5. **AERA/APA/NCME**：*Standards for Educational and Psychological Testing*。テスト得点の利用目的、妥当性、解釈、技術的限界を考慮する。https://ncme.org/resources/books/testing-standards/
6. **米国教育科学研究所（WWC）**：*Organizing Instruction and Study to Improve Student Learning*。学習間隔、解説例と自力の課題、深い理由を考える問いなどを推奨する。https://ies.ed.gov/ncee/wwc/PracticeGuide/1
7. **W3C**：WCAG 2.2（入力の誤り特定、ラベル、アクセシビリティ）。https://www.w3.org/TR/WCAG22/

研究を参照した事実は、ここで追加した2ケースが認知能力を測定する妥当な試験であるという証明にはならない。

## 2. 前提を疑う担当：最初の案を反証

| 初回仮説 | 反証・リスク | 更新した方針 |
|---|---|---|
| 90問を拡張すればよい | 量が増えても実務判断を観測できない | 今回は四択・新問を増やさない |
| A/B/Cで正解が増えれば能力向上 | 1問の難度差、時期、事前経験の影響が大きい | 得点の改善率を出さず、判断メモを原文で保存 |
| 説明をAIが自動採点すればよい | 模範解答の類似度は正しさ・権限・判断の安全性を保証しない | 自動採点・合格判定なし、外部評価票を用意 |
| 同じケースをもう一度書けば転用力を測れる | 以前に読んだ正解の再生にすぎないかもしれない | **スポーツ映像の許諾**と**チケットの在庫連携**という異なる2案件を使う |
| 第三者へ送れば外部評価済み | 評価者の利害や独立性、評価基準の一致は未検証 | 評価依頼票を生成するが採点結果の存在を装わない |
| 日常業務の生データを扱えばよい | 機密・権利・個人情報のリスク | 架空の業務台帳と発言ログのみ使用 |

## 3. 能力モデル→証拠モデル→課題モデル

### 能力（何ができるべきか）

期限と権限に制約がある案件で、発生した事象と将来の不確実性を切り分け、資料の確実性を吟味し、複数の対応策と判断条件を示して適切な権限者へ意思決定を上げる。

### 観察可能な証拠（5項目）

| 能力を表す主張 | 観測する証拠 | 根拠が不足する兆候 |
|---|---|---|
| 資料を正しく読む | 事実の数量・時点と原資料IDを示す | 担当者の推測を事実にする |
| 問題とリスクを区別できる | 発生済み事象と将来のリスクを分離する | 期限切れを単なる懸念として扱う |
| 選択肢を比較できる | 少なくとも2案と条件・便益・損失を記述 | 権利・在庫などの安全制約を無視 |
| 責任を具体化できる | 決裁者、担当者、期限、判断事項を書く | 権限者不明のまま結論を出す |
| 判断に必要な反証を考える | 不明な契約・ログ・検証の取得担当と時点を示す | 「大丈夫そう」で終了する |

### 課題モデル

ケースA「映像公開の権利未承認」：台帳上40クリップ中12本未許諾。営業担当の契約発言は未照合。金曜配信の変換遅延は現時点ではリスク。

ケースB「チケット発売の在庫不整合」：12,000席中270席に発生済みの不整合。土曜のAPI上限到達は未発生のリスク。販売担当の「全部売れる」は未照合の意見。

それぞれで、事実・問題とリスク・選択肢・権限・追加確認の5欄を埋める。**単なる文章量ではなく、根拠と判断の質が重要**であり、12文字以上の入力制限は空欄検知に過ぎない。

## 4. 次のリサーチ計画（情報の価値順）

| 優先 | 不確実性 | 一次情報・生データ | 方法・判断への影響 |
|---|---|---|---|
| P0 | 正しい推奨と重大な見落としを分けられるか | 専門家2名の独立した答案評価・反対意見 | 選択肢が複数成立する条件を抽出して基準を改稿 |
| P0 | 2ケースが同じ能力を測るか | 学習者の解答原文・時点・所要時間、未提示問題 | 思考発話法（Think-Aloud）、必要条件の比較 |
| P0 | 既存データの保護ができるか | localStorageバックアップ、旧版JSON、Safari実機の中断・復元 | 事故があれば機能の利用を制限 |
| P1 | 第三者の評価に一致があるか | 2名の独立評価票を同じ5項目で記録 | 不一致の理由を確認。十分な件数なら一致率・重み付きカッパ等 |
| P1 | 実務に転用できるか | 初見の別案件・実際の判断メモ（匿名・許可済み） | 専門家による評価。小規模な結果を一般化しない |
| P2 | 専用アプリが最適か | 学習時間、利用操作、外部サービス費用 | フォーム・紙・既存ノートと比較して継続投資を判断 |

現時点で外部評価・実利用ログの分析は未実施。**回答原文の収集には本人の明示的な提供が必要**。

## 5. 再リサーチ：初回結論から変えたこと

初回方針「問題形式を増やして測る」を見直し、実際のPMOが行う行動に焦点を絞った。PMIの実務上の整理に合わせてリスクと問題を区別し、ETSの枠組みに合わせて5つの観察可能な判断を定義した。

ただし、**2ケースの難易度を等化していない**ため、AからBの改善を得点で示さない。評価票にも計量化を強制せず、0／1／2または判断保留と、具体的な記述根拠・危険な見落としを記入できる欄を設けた。

### 最低限の反証条件

- 専門家が重要な別解を見つけ、評価基準に不足がある → 評価基準を修正。
- 2名の評価者が一貫して異なる評価をする → 基準を分解するか、得点化をやめる。
- 学習者が誤った安全・権限判断を見落とす → 事例を修正し、補助教材を優先する。
- 入力や再読込で提出文が消える → 機能の継続利用を止め、保存機構を修正する。

|---|---|---|---|

## 7. 実装と品質検証

- `cert-lab-evidence-data.js`：2ケースの架空原資料、5つの評価基準、重大な判断ミスの確認事項、評価票生成。
- `cert-lab-evidence-ui.js`：判断メモの入力、下書き保存、初回提出の固定、提出後だけ参考例を表示、別案件の開放、Markdownでの外部評価票。
- `cert-lab.js`、`index.html`、`cert-lab.css`：既存ラボに新しい実務判断画面を統合。
- `tests/cert-lab-evidence.mjs`：問題の構造と5つの評価基準の対応、外部評価票から参考例が除外されること、提出文のスナップショット、既存90問の保全。
- `tests/cert-lab-browser.mjs`：デスクトップChromiumとモバイルWebKitのUI操作、参考例の封印、入力不足、初回提出の固定、別ケースの開放、ブラウザ再読込。
- 旧 `state.certLab` と `state.certLab.evidencePilot` を分離する。端末内データの外部送信は行わない。

テストに合格しても、**実際のiPhone Safari・VoiceOver・専門家の独立査読が完了したことにはならない**。

## 8. 次回の投資判断

**今すぐすること**
- 新ケースの評価基準についてPMO経験者など2名に独立査読を依頼。
- 重要な安全・権限判断で許容される別解を整理し、採点基準を修正する。
- iPhone Safari実機で下書き・提出・評価票の保存、旧JSONとの互換性を確認。

**後回し**
- 財務・統計への同型ケースの拡張（PMOの基準の妥当性を確認してから）。
- 自動採点や適応学習の最適化（評価の一致度を確認してから）。

**行わないこと**
- 小規模な2ケースだけでの実力認定。
- 記述の自動合否判定、根拠のない進捗点数。
- 端末内メモの無断クラウド保存。
- 未調査のシラバス完全網羅の主張。

**停止条件**：実際の利用者が成果物を作らない／第三者評価に一貫性が出ない／操作負荷が学習を妨げる場合は、画面増設を停止し、既存問題やオフライン演習へ投資を戻す。

本実装は、学習効果の「結論」ではなく、それを確かめるための「証拠をつくる場」の最小試作である。
