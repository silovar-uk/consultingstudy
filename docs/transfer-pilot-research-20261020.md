# Consulting Study｜リサーチ・再リサーチ・実装・評価計画（2026-10-20）

## エグゼクティブサマリー

**追加したのは「学習効果が証明された装置」ではなく、学習効果を検証するための最小プロトタイプである。**

- 既存の43章、資格21単元、独自問題90問を維持する。
- 財務・統計・PMOの3領域について、**初回確認（A）、別事例の練習（B）、暫定3日後の初見評価（C）**を各1問ずつ用意した。追加の9問は**評価用プロトタイプ**として、従来の90問の正答率や進捗に合算しない。
- Aの正答を最初から開示せず、Bの答えを説明してから、Cの問題文を試行的に3日間非表示にする。
- 保存形式は `state.certLab.transferPilot` へ新設。従来の `state.certLab.attempts`、`deepPractice`、`notes` を上書きしない。
- 画面では3段階の回答結果を独立に表示し、1人・3問の結果を学力向上の因果的証拠と称さない。
- 日本時間・世界時をまたぐ条件を単純化するため、B回答の時刻から正確に72時間後にCを解放する。3日という間隔は研究上の最適間隔ではない。
- 端末時刻・公開JavaScriptを使う仕組みのため、厳格な試験監督や不正防止には使えない。

## 第1工程：一次情報・研究

| 文献・基準 | 調べたこと | このアプリに採用する判断 | 適用できない推論 |
|---|---|---|---|
| Roediger & Karpicke, 2006（https://doi.org/10.1111/j.1467-9280.2006.01693.x） | 読み返す学習と想起練習を、数分・2日・1週間後の保持で比較 | 後日の再評価を検討 | 3日の間隔や本アプリの効果が最適・実証済みとはいえない |
| Butler, 2010（https://doi.org/10.1037/a0019902） | 一週間後に元の問題・同領域の新しい推論問題・別領域の新しい推論問題を提示 | 同じ問題の再回答と、新しい事例への転用を区別 | 別設定の3問が等価な難易度と保証できない |
| Corral et al., 2025（https://doi.org/10.1016/j.learninstruc.2025.102219） | 1回の練習と複数回の練習・即時と一週間後の検証を比較 | 練習回数と遅延を独立した変数として扱う | 1回の別事例練習だけで転移能力が伸びたとはいえない |
| AERA・APA・NCME 2014 Standards（https://ncme.org/resources/books/testing-standards/） | テストの得点だけでなく妥当性と利用目的を検討 | 成績・資格判定・実務能力認定を混同しない | 自動テスト成功を心理測定上の妥当性とみなさない |

各情報源は一次論文・学会/発行団体を優先するが、本機能に関する効果検証の代わりにはならない。

## 第2工程：最初の監査の結果

GitHub mainの実際のデータから2026年10月20日に全件台帳（`docs/question-audit-20261020.csv`）を作成。

- 既存四択63問の正答キー・解説はコード上で確認できる。**4選択肢別に一つずつ根拠を付けた形式ではない**。
- 多形式の27問には6種類の形式、能力のメタデータ、採点・自己点検の実装がある。
- うち8問には4選択肢それぞれの解説がある。
- 自己点検の対象となる記述・誤り訂正は6問で、**専門家間の採点一致度は未評価**。
- 出典URLは主に領域・試験の公式案内であり、**90問それぞれの論拠の直接出典とは限らない**。
- 本開発以前には初回と初見の遅延評価を分ける仕組みがない。
- 90問すべてについて、専門家が各選択肢・論理・実務適合性を独立に査読した証拠はない。

機械的なコード検査で見つからない問題は、外部査読が必須である。

## 第4工程：再リサーチによる初回仮説の更新

### 仮説1「復習すれば実力が伸びる」

**修正**：元の問題を再度解く成果と、初見の応用課題を解く成果を区別する。Butler（2010）の転移研究はこの区別を支持するが、実際の企業の経営判断への汎化は証明しない。まずA/B/Cという異なる問題を用意する。

### 仮説2「一度の練習で応用力を測れる」

**修正**：Corralら（2025）の実験では練習回数と遅延の条件で結果が変わった。一度のB練習からCの結果が良くても因果効果とは断定せず、「より厳密な比較設計に向けた記録」と扱う。Bを繰り返すか、Cに別の同等問題を用意するかは、試用後に判断する。

### 仮説3「数値を出せば客観的な能力評価になる」

**修正**：A/B/Cの難易度は等化していない。単純な得点差は能力向上を測る尺度として未検証である。まず問題ごとの結果のみ表示し、学習効果の改善率を算出しない。

## 第5工程：学習システムの5層構造

1. **知識体系**：既存の43章、21単元と、公式シラバスの参照・不足分野。
2. **学習経路**：講義→クイズ→多形式演習→自分の説明→初見評価の3段階。
3. **演習体系**：既存90問と、評価専用の3領域×3問を分離して収録。
4. **成果の評価**：初回A／別事例B／後日Cの回答、記録時刻、正誤を別管理。能力を実証したとの断言はしない。
5. **次の学習提案**：実力検証タブを追加し、B後に待機理由と関連教材への導線を提供。既存の「今日の一手」を一挙に置き換えない。

## 受入条件と品質ゲート

- 新しい3領域のA/B/Cが各1問ずつ存在する。
- B完了前にはCを表示しない。B完了後も72時間が経過するまでCの設問・正解を画面に出さない。
- 72時間の境界前後のテストが通る。
- 入力が空の場合や選択が不正の場合、正答として扱わない。
- 既存90問・旧学習履歴・ノート・バックアップを維持。
- CIのNode検査に加えて、PC ChromiumとWebKitモバイル相当で画面操作を確認。
- デバイス時刻改変や静的ソースの閲覧による回避を防ぐセキュア試験の仕様ではないことを明示。

**学力が上がった**、**実務能力を認定できる**、**科学的に最適な間隔**、**初見の難易度が等しい**、という主張はしない。

## 次期バックログ：作業量ではなく検証の質

1. 【P0】90問と新9問の専門家査読（正答・誤答・説明・場面の正確性）
2. 【P0】A/B/C問題の比較可能性と、全問題の直接根拠の整備
3. 【P1】iPhone Safari実機・VoiceOver・データ復元確認
4. 【P1】本人の同意を得た匿名小規模試用、初見課題への転用の確認
5. 【P2】同一能力の複数の評価問題を作り、学習条件・難易度の違いを調整
6. 【P3】必要な場合のみ、問題をさらに増補する

### やらないこと

- 根拠のない実力スコアや合格確率の表示
- 採点できない自由記述の見かけだけの自動評価
- 未検証の学習理論を「AIが最適化した」と表現
- 端末データを無断でクラウドへ送る設計

最も重要な次の問いは、**「この仕組みで初見問題に正答できたことと、実際に仕事で判断できることはどうつながるか」**である。次の実装規模は、この検証結果に基づいて判断する。
