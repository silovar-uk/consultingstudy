# Consulting Study｜守破離・タスク中心UX再設計（2026-10-20）

## 結論

**最初に学習タスクを探させず、前回の続きに戻す。** 現行のトップレベル11入口とラボ内9タブという重複ナビゲーションを、利用頻度が高い入口4つ＋必要なときに開く補助機能に変更した。既存機能と旧データ形式を削除しない。

### 前提批判

- 「ページを増やすほど便利」は成り立たない。ホーム／ラボ内「今日」、教科書／教材、演習／問題などは情報設計上重複する。
- 「読了率や回答率の数値を毎回見せる必要がある」は未検証。主画面の進捗情報を開閉可能な補助領域に移動。
- 「新しいAI評価が必要」は未検証。まず再開と作業文脈を改善。
- 「UIを作れば学習効果が上がる」は未検証。操作指標と実務成果指標を分ける。

### ホームの四つの目的

1. 「数字を読みたい」→ 既存の財務ワークスペース
2. 「判断を整理したい」→ ラボ内PMO判断メモ
3. 「知識を身につけたい」→ ラボ内教材
4. 「実力を確かめたい」→ ラボ内のA/B/C初見評価

初回利用でラボ歴がなければAtlasの次の教材を案内する。ラボの学習歴があれば最後に開いた作業タブに戻す。**ブラウザ内の情報を参照しているだけで、クラウドの利用履歴収集ではない。**

## 検証すべき一次データ・生データ

コード・画面操作から確認できる事実と、実測していない指標を分ける。

- **確認済み（自動テスト）**：ナビの4入口、目的別遷移、戻る／進む、WebKitとChromiumでの画面遷移、PMO二案件の初回提出固定と復元、既存問題・保存との互換。
- **今後の実測が必要**：学習開始までの所要時間、誤タップ、画面の行き来回数、途中離脱、実機iPhone Safariでのソフトキーボード表示、VoiceOver、実務成果物の質。

本番利用者の操作ログは収集しておらず、改善率などを作り出さない。

## 外部手法と受入基準

- Nielsen Norman Group、*Progressive Disclosure*：通常使う操作を優先し、詳細は必要時に開く。https://www.nngroup.com/articles/progressive-disclosure/
- GOV.UK Design System、開始画面の指針：目的と開始操作を明示する。https://design-system.service.gov.uk/patterns/start-using-a-service/
- WCAG 2.2：タップ領域、キーボード操作、フォーカスの可視性を確認。https://www.w3.org/TR/WCAG22/

### 小規模な利用者テストの計画

評価者には画面の変更目的を事前に知らせず、次のタスクを旧UIと新UIで操作してもらう。順序の偏りを避けるため提示順を入れ替える。

| 利用者タスク | 暫定の受入目安 | 記録 |
|---|---|---|
| 開いた後、前回の作業へ戻る | 2操作以内 | 操作数、時間、失敗回数 |
| 未知の教材を見つける | 説明なしで達成 | 迷った場所、探索時間 |
| 入力中断後、同じ答案から再開 | 入力消失なし | 実データの復元確認 |
| PCで資料を見ながら判断メモを書く | 往復操作の減少 | スクロール・目線・所要時間 |
| iPhone Safariで資料を見て書く | ページが横にはみ出さず編集可能 | 実機録画、キーボード干渉 |
| ブラウザの戻る・進む | 直前の主要画面に復元 | 画面とURLを照合 |

### 継続投資の判断

- **改善**：操作数・時間・誤操作が減り、利用者の作業成果に副作用がない場合は拡張。
- **見直し**：詳細メニューの発見率が悪い、旧機能の利用が阻害される、バックアップの復元に問題があれば設計を変更。
- **停止**：新UXの利用によって操作が増えたり、学習の成果が悪化する場合は旧構造へのロールバックを優先。

## 既知の限界・次期バックログ

1. **iPhone Safari／VoiceOverの実機検証：未実施**。CIのWebKitモバイルエミュレーションは代替にならない。
2. ラボ内の細かな問題ID・入力欄まで共有できるパーマリンクは未実装。主要画面はURLに反映。
3. **思考の差分**は提案として維持するが、二つの答案の違いを自動採点・実力認定する機能は作らない。
4. 「その他の機能」の発見率・目的別導線の実使用率は未測定。必要ならメニューの表示を再検討する。
5. 作業記録の `localStorage` はブラウザ依存。既存の設定画面でJSONのバックアップを定期的に取る。
